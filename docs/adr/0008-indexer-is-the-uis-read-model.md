# The Indexer is the UI's read model; the chain stays authoritative for the protocol

Two read endpoints reached the chain live on every request, uncached, and the Dashboard polled both every ten seconds, so viewer count multiplied the bill in a way idle traffic never did: thirty people watching a demo would have cost more than the rest of the backend combined. The rebuild moves the browser's only path to protocol state onto the Indexer's Postgres mirror. One consolidated endpoint returns the Pool, the current Epoch, the open Round, the caller's Player, operator status and chain time in a single response, extrapolated from the last observed Clock sysvar read so serving it costs no call, and the browser polls that instead of reading the chain. This inverts the frontend's own read module, which declared the chain authoritative and the API a cache: a cache may be bypassed for a fresher read, and after this effort the browser has nothing left to bypass to. The chain stays authoritative for the protocol; the Indexer becomes authoritative for what the UI shows. The connected wallet's own token balance is the one read left in the browser, against a public endpoint, because it is per-visitor and not a program account the Indexer has reason to hold.

The trade is freshness for a bill that does not scale with viewers. A screen can be up to one poll interval stale, and a poll costs the Indexer the same whether one visitor or thirty are watching. Round length also moves from 60 to 90 seconds as part of the same budget: round count is the multiplier on the largest remaining line, transaction sends, and 90 seconds projects to roughly 560k credits a month at idle against a 1M free allowance. That projection comes from the provider's published per-method credit table, not a measured bill, so round length is the cheap lever if the real number disagrees: moving to 120 seconds halves the round-linked lines again, one parameter call, no redeploy.

Considered and rejected: keeping the chain-authoritative reads and caching them harder. A longer cache narrows the per-viewer leak without closing it, since any endpoint added later without a cache reopens it, and it does nothing for the Operator's own polling, which was the larger share of the idle bill. Server-sent events or a socket from the backend to the browser were also considered and dropped: the consolidated endpoint at a short poll interval is simpler to reason about and cheap enough, and push is worth revisiting only if the interval or the perceived latency becomes a complaint.

Consequence: a stale-looking screen is now an Indexer bug rather than an RPC failure. The debugging reflex that used to serve, blame the endpoint, points at the wrong component once the browser has no chain read left to fail.
